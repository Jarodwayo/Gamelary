# Commentaires de code

Ce projet sert de vitrine en entretien d'embauche. À chaque ajout ou
modification de code, commente les décisions techniques et la logique
métier non triviales (le POURQUOI, pas le COMMENT/QUOI déjà lisible dans le
code) : choix d'architecture, contraintes de plateforme, cas limites gérés
volontairement, hypothèses sur les données. Évite les commentaires qui ne
font que reformuler ce que le code dit déjà.

Tiens `ARCHITECTURE.md` à jour à chaque changement structurant (nouvelle
dépendance, nouvelle intégration API, changement de stratégie de cache ou
de navigation).
